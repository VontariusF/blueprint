# Context, profiles and resources

Keep methodology, reusable preferences, shared inventory and project decisions distinct. Read explicitly supplied/project-designated references first. Earlier project choices do not silently become standing rules.

Load ../profiles/default.json or the selected hackathon/startup preset. Presets supply planning priorities and provisional visual defaults. Intentionally layered personal/organization profiles can extend these. Explicit project choices override style defaults; standing access/spend restrictions remain effective until the user changes them. Surface consequential conflicts with a recommendation. Record references/revisions of reusable context used. Later shared changes flag affected projects for review, not silent rewriting.

No personal compute, accounts, subscriptions or credentials are bundled. The example inventory under ../assets/ is a schema, not actual access. Ask for an inventory location only when missing context matters; continue research meanwhile. Fixtures are not live connections.

## Confirm relevant resources

Reuse established access and locations; verify mutable capacity/cost/suitability when relevant. Availability does not imply project allocation. Record capability, rationale, location, access reference, status, restrictions, verification evidence and affected milestones. Reference credential stores/connections rather than secret values.

When research identifies a needed resource absent from inventory, agree its role and clarify how access can be made possible: account/connection/setup, responsible person, required budget and dependent milestone. Design around explicit pending dependencies while progressing elsewhere. Design readiness and milestone execution readiness are separate. Planning purchase/provisioning does not authorize executing it.

Allow implementation discretion within confirmed budgets and access. Limits vary by project. Do not assume universal budgets or silently allocate shared credits.

## Ambiguity and reuse

Track consequential unresolved questions with options, recommendation, affected work, independent work and resolver. The user may brainstorm with their main research agent and return a resolution. Continue independent work; if all useful actions depend on an answer, checkpoint honestly. Record resolutions with rationale and consequences. Reopen settled choices for evidence, conflict or user direction.

Update shared profiles/inventory only when the user designates reuse. Clarify unclear reuse scope while progressing project work. Keep a one-project selection local otherwise. Report the shared update. Do not rewrite the overarching method for one project's stack or aesthetic.
